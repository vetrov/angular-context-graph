# MVP implementation decisions

The matrix in [angular-relationship-research.md](angular-relationship-research.md) remains the graph contract. This implementation addresses snapshot persistence, unit-level incremental indexing, evidence-backed queries, and CLI/MCP delivery. It imports the proven extraction passes and keeps unimplemented relationship families visible.

| Decision            | Implementation and boundary                                                                                                                                                                                                                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Store               | Node's built-in SQLite with foreign keys, indexed forward/reverse adjacency, immutable snapshots, and a transactional current-snapshot pointer. The store API is isolated in `src/store.mjs`.                                                                                                                                  |
| Compiler isolation  | A child process per affected unit resolves the target's installed Angular/TS packages. Angular/TS passes share that unit's compiler program. Timeout and cancellation preserve the last published snapshot.                                                                                                                    |
| Invalidation        | Compiler/config filesystem reads and glob directory membership, failed resolution probes, resource reads, real paths, package manifests, configs, and lockfiles are fingerprinted. Recompute a whole affected unit.                                                                                                            |
| Registry            | Workspace-qualified import IDs with a persisted legacy map. Angular/TS declarations share identities; occurrence/context IDs include the unit. Stable across unchanged snapshots; moves/renames/offset changes are not migrated. Colliding class names fail validation.                                                        |
| Source occurrences  | Every imported observation has a separate occurrence record and original span; templates have owner records. Original endpoint semantics are identified as the prototype compatibility view. Explicit lexical locals/views and fully occurrence-originating extraction remain partial.                                         |
| Uncertainty         | Target resolution, semantics, runtime possibility, provenance, and context are separate fields. Legacy confidence survives only as an imported field. Issues, unresolved calls, unrepresented declarations, opaque provider regions, candidates, and missing-in-model results persist.                                         |
| Coverage            | All 26 matrix families are represented per unit. Proven subsets remain partial, absent extractors unsupported, and expected population unknown where the prototype has no denominator. Legacy template completeness is stored separately.                                                                                      |
| Build variants      | Identity includes target/configuration and builder settings. File replacements/custom builders are unsupported; no effective build config is guessed. Explicit projects analyze their tsconfig program closure.                                                                                                                |
| Queries             | One service shared by CLI and MCP. SQL search with exact-name ranking and service-role filters; compact defaults with full DTO/evidence access. Snapshot-bound cursors, named unit selection, bounded paths. Immutable unit manifests are cached; input checkpoints last at most one disclosed second. Queries do not compile. |
| Provider resolution | Requires an explicit injector context. Registration selection and implementation evidence remain separate. Different view/content/route/application placements never become one global service winner.                                                                                                                         |
| Unused policy       | Framework/template/host references are exclusions. No observed incoming usage remains blocked by dynamic/public/test/framework coverage; there is no deletion recommendation.                                                                                                                                                  |

The indexer caps derived Angular expansion at 5,000 injector contexts and 20,000 resolution records per unit, and compiler workers at 120 seconds. Crossing a bound fails that rebuild and retains the last snapshot. Traversal bounds and query truncation are separate from extraction coverage.

## Similar projects reviewed

[CodeGraphContext's server](https://github.com/CodeGraphContext/CodeGraphContext/blob/main/src/codegraphcontext/server.py) separates graph building, persistent database management, jobs, and query handlers. Its [code finder](https://github.com/CodeGraphContext/CodeGraphContext/blob/main/src/codegraphcontext/tools/code_finder.py) provides callers/callees, graph relationships, ambiguous-location reporting, and explicit result truncation. We adopted the shared persisted graph, direct CLI querying, and visible bounds. Angular usage candidates additionally require the matrix's framework/public/test coverage policy and compiler-resolved identities.

[trace-mcp](https://github.com/nikolai-vysotskyi/trace-mcp) demonstrates useful framework context and reverse-impact queries over an index. Its [indexing pipeline](https://github.com/nikolai-vysotskyi/trace-mcp/blob/master/src/indexer/pipeline.ts) uses content-change gates, handles removed/out-of-scope files, and bounds incremental scope before falling back to broader work. We adopted unchanged-input reuse, explicit removal/parity checks, and small context/impact queries. Our first incremental boundary is the compiler unit; finer file/pass invalidation needs separate Angular proofs.

These are architecture references. This MVP does not claim their API compatibility, framework inventory, benchmark results, or runtime guarantees.

## Acceptance evidence

`npm test` passes all **75 tests**, including the original 50 proof tests plus persistence/query/CLI/MCP acceptance tests. The suite checks restart, deterministic export/import, original source spans, corrupt-edge rejection, writer serialization and killed-writer recovery, compiler failure retention, stale evidence reads, conflicting compiler reads, source/HTML/config/lockfile invalidation, add/delete/rename parity, overlapping units, contextual providers, bounded paths/cursors, framework-only usage, and an actual stdio MCP client handshake and tool calls. Query acceptance additionally checks compact/full parity, SQL search without whole-graph loading, service-role aliases, nested DI value providers, shared-registration evidence, a skipSelf override that prevents sharing, named variants, multi-provider order, source-edit detection, and checkpoint expiry.

`npm run test:matrix` passes **51 checks per pair**: the original proofs plus the version-isolated indexing/warm/full parity test on Angular 20.3.33/TS 5.9.3, Angular 21.2.25/TS 5.9.3, and Angular 22.2.1/TS 6.0.3. Fixture evidence does not establish every patch version.

A read-only source-mode Workplace Hub indexing run persisted **27,282 entities and 20,771 observations** in **4.3 seconds**, retaining **402 unrepresented template occurrences** as issues. The query proof reads the original `save` template span and follows the handler's injected field through a contextual resolution to the selected SupplierFacade registration and implementation. [Saved validation evidence](mvp-validation.json) records the versions, counts, source locations, and path semantics. Measurements are local observations, not service-level targets; they include evidence/coverage/occurrence records rather than only declarations and primitive edges. The demo workspace was read without building or modifying its source. Larger-workspace benchmarking, compiled-consumer MVP runs, relocatable bundles, watchers, and finer incremental invalidation remain follow-up work.

## Query efficiency update

The RequestListService investigation exposed repeated full coverage matrices, large DTO payloads, and duplicate text/structured JSON delivery. The server now sends compact structured results and a short text receipt without duplicate JSON, including full-detail queries. Full coverage/DTOs are opt-in, while evidence snippets remain available by ID. `explain_injection` answers the provider/dependency/token/sharing question in one call, with explicit variant choice, source locations, candidates, missing results, and runtime assumptions. It compares selected registrations and their modeled owning injector; it never reports observed runtime object identity.

[Query validation](query-validation.json) records read-only measurements against the existing three-variant Workplace Hub index. The focused DI answer preserves HTTP as unresolved and DemoContext as candidate while selecting the local ListQueryState and the `requests` value for LIST_KIND. These measurements describe query time and JSON characters, not client token usage or end-to-end agent speed.

The new source-edit acceptance test found that Angular's compiler host can bypass a wrapped `readFile` when loading TypeScript. Tracking `getSourceFile` now validates compiler text against the original file and fingerprints it, including declaration files. Older input manifests are insufficient to verify source freshness; their snapshots remain readable but report an outdated extractor until explicitly rebuilt. The Workplace Hub index was left unchanged for the query comparison. Extraction fingerprints now cover extraction/model/discovery/input-tracking code instead of query and transport modules.
