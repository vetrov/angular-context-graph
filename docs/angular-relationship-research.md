# Angular relationship matrix and indexer handoff

Research snapshot: 6 October 2026. This document is the handoff for a future Angular-aware TypeScript indexer and MCP server. It specifies the relationships to research, the graph records needed to represent them, extraction approaches, proof requirements, and implementation dependencies. It is a design proposal wherever the prototype has no implementation; proposed edge names are not claims about current output.

The objective is one connected graph across Angular declarations, templates, framework configuration, services, and ordinary TypeScript code. Useful queries include contract impact, component/service dependencies, feature and route context, provider selection, framework entry points, and unused-symbol candidates. “All Angular connections” is an extensible research inventory: Angular versions and third-party APIs can add families, and static analysis cannot determine every runtime target.

## Evidence and terminology

- **Proven** means the saved prototype establishes the listed subset on its fixtures and reviewed demo cases. It does not mean exhaustive coverage of the family.
- **Partial** means a prerequisite/subset is proven but the main additional graph relations remain unimplemented.
- **Pending** means no dedicated semantic extraction proof has been completed.
- **Existing** edge names are emitted today. **Proposed** names define a suggested schema for the next implementation.
- **Resolved target** describes declaration identity. **Static declaration** describes configuration/source facts. **Candidate** describes a possible contextual/runtime relationship. These are independent of whether a site executes.

Each family needs independently reviewed expected declarations and edges; positive, negative, alias/inheritance, scope, and dynamic cases; original source spans; shared TS identity; supported-version and compiled-library evidence where applicable. Unknowns must be persisted as records, rather than disappearing when there is no edge.

Current validated pairs are Angular **20.3.33 / TS 5.9.3**, **21.2.25 / TS 5.9.3**, and **22.2.1 / TS 6.0.3**. Support is demonstrated for these patch versions. Capability detection and new fixtures are required for other releases and APIs.

Latest saved evidence: **50 fixture tests pass per pinned pair (32 earlier tests plus 18 core proofs); 24 additional real-project core checks pass in source/compiled-library modes.** The earlier 10 expression checks remain saved as a separate milestone. The independent binding audit covers 304 source bindings; the compiled UI consumer preserves all 668 application-owned Angular relationships. The latest expression graph emits 485 template calls and 1,614 template references in source mode, or 442 and 1,542 in compiled mode. Both modes retain **402 compiler-resolved occurrences whose declaration forms the prototype cannot represent**. A zero unresolved-call count therefore does not imply complete expression coverage.

## Shared graph contract

Use four distinct layers. Most incorrect global dependency claims come from collapsing them.

| Layer              | Suggested records                                                                                                                         | Purpose and identity                                                                                                                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Declarations       | Symbol, with roles Component/Directive/Pipe/Service/NgModule; Method, Function, Property, Parameter, TypeMember                           | One canonical declaration identity shared by Angular and TS. Angular roles are facets, not duplicate class nodes. Receiver class and actual inherited declaration can differ.                                                      |
| Source occurrences | Template, View, ElementSite, ExpressionSite, BindingSite, PipeSite, Local, Query, InjectionRequest, ProviderRegistration, RouteDefinition | A concrete source construct has its own identity and location. Two uses of one class, two identical providers, or two same-path route definitions remain distinct.                                                                 |
| Context            | Workspace, Project, CompilationUnit, Application, PlacementContext, InjectorContext, RouteMount                                           | Identifies build variant and logical placement. Contexts are static models of possible placements, not observed runtime instances. Reusing one component or routes array in two parents can yield different DI/navigation answers. |
| Evidence           | Observation, AnalysisIssue, CoverageRecord, Derivation                                                                                    | Stores why a relation exists, which analysis produced it, what is unknown, and which source/config dependencies invalidate it.                                                                                                     |

Additional domain records include InputContract, OutputContract, Token, ProjectionSlot, FormControlModel, ReactiveNode, FrameworkEntryPoint, Resource and Package. A token record references its declaring symbol/value; a string token uses its statically known primitive value within the analyzed program. Two `new InjectionToken('same label')` declarations are different tokens. A class used as a token links to the same TS class declaration.

### Identity, spans, and edge fields

Recommended identity is workspace/package identity + logical source URI + declaration/container path + disambiguator, assigned through a central symbol registry. Track canonical real paths for resolution and logical paths for display. Anonymous constructs need a syntactic container/ordinal or persisted identity mapping. Offsets locate an occurrence in a snapshot; they are not a durable identity across edits. Promise stability across unchanged snapshots; rename/move migration is separate work.

The spike currently uses absolute `file#Class` IDs and offset-based member IDs. Preserve an import/migration map when adopting the production registry. These IDs do not survive renames/moves, and offset changes can change member identity. Detect namespace/nested/duplicate-name collisions. Keep overload signatures and merged declarations attached to a symbol, while retaining the chosen signature and implementation on call observations. A `.d.ts` declaration and its source implementation remain separate unless a verified declaration/source map or package build mapping links them; equal names are insufficient.

Every occurrence/observation needs `workspaceId`, `compilationUnitId`, `snapshotId`, `extractorVersion`, exact Angular/TS package versions, `familyId`, `location`, and relevant `ownerSymbolId`/`siteId`/`contextId`. A location is original file URI, zero-based UTF-16 `start` and exclusive `end`, and one-based line/column. Store expression-name spans separately from enclosing constructs and metadata argument spans. Inline escapes, transformed resources and indirect constants require a verified source map or an explicit location limitation. Generated `.ngtypecheck.ts` and generated rendering instructions are not user-source locations.

| Edge/observation field               | Required meaning                                                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`, `from`, `to`, `siteId`       | A directed, schema-defined relation; target kinds validated. Many occurrences can support the same aggregate relation.                                  |
| `targetResolution`                   | `resolved`, `candidate-set`, or `unresolved`; an unresolved record need not have `to`.                                                                  |
| `semantics`                          | `declaration`, `reference`, `compile-time-call`, `contextual-resolution`, or `possible-runtime-flow`.                                                   |
| `provenance`                         | `typescript-checker`, `angular-template-checker`, `angular-metadata`, `static-evaluator`, `api-rule`, or `runtime-observation` if separately collected. |
| `contextId`, `conditions`            | Context and branch/defer/route/guard/platform constraints. A resolved target can still be conditionally activated.                                      |
| `evidenceIds`, `derivationRule`      | Original observations that justify a derived edge; rules versioned and explainable.                                                                     |
| `reason`, `candidateIds`, `external` | Uncertainty reason, bounded known candidates, and whether implementation is outside the indexed closure.                                                |

Do not convert the prototype's `confidence: exact/static` into a single probability. Exact source/target mapping and runtime possibility are different dimensions. Preserve the legacy field when importing old evidence, then populate the explicit dimensions.

Proposed primitive relations are in the matrix. Class-to-class aggregates such as `DEPENDS_ON` or `USES_SERVICE` should be derived views with evidence paths. For example, component → injection request → token → contextual resolution → provider → implementation supplies a richer answer than component → service alone. Reverse dependencies are reverse traversals over stored edges, not a second independent extraction.

The prototype's component → `TEMPLATE_CALLS` → method can remain an aggregate compatibility view. New extraction should also store component → template → expression occurrence → method. A binding, emitted output and listener can then be joined at the correct component site without merging unrelated instances.

In the spike, `BINDS_INPUT`, `LISTENS_OUTPUT` and `USES_PIPE` also originate at the owning component, with a site/location on the edge. The matrix proposes occurrence-based origins for the normalized graph. Preserve old endpoint semantics in a compatibility view or use a schema-version migration; do not silently change endpoints under an existing consumer contract.

## Extraction API map

| Code  | Mechanism                                                                                                                                                                          | Availability and use                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TS    | The target program's public `TypeChecker`: `getSymbolAtLocation`, `getAliasedSymbol`, `getTypeAtLocation`, `getResolvedSignature`; AST traversal and TS module resolution          | Implemented for ordinary dependencies. Use the same program as Angular. Recognize API identity through resolved imports/exports, including aliases and namespaces; never infer semantics from a bare identifier such as `inject` or `effect`.                                                                                                                                                                                                                                                                     |
| TTC   | `NgtscProgram.compiler.getTemplateTypeChecker()`, `generateAllTypeCheckBlocks`, `getTemplate`, `getDirectivesOfNode`, `getSymbolOfNode`, `getDirectiveMetadata`, `getPipeMetadata` | Implemented private API adapter. Angular 20/21 expose older symbol fields; 22 needs `getTsSymbolOfSymbol` / `getTypeOfSymbol` in relevant cases. Matched directives for the particular node, not all directives reported by a desugared symbol, are authoritative.                                                                                                                                                                                                                                                |
| META  | TTC `getNgModuleMetadata`, `getOwningNgModule`, directive `imports`, `deferredImports`, `hostDirectives`; compiler `getDirectiveResources`                                         | Additional methods/fields inspected in installed 22.2.1 declarations; some source scope/import/declaration facts are now extracted with TS/static rules; broader compiler-normalized metadata extraction remains proposed. `getPrimaryAngularDecorator` explicitly excludes `@Injectable`, so service detection needs TS reflection. Query member names alone do not expose complete query predicates/options.                                                                                                    |
| LOCAL | TTC `getExpressionTarget(expression, component)` and symbols for references/variables; Angular template AST                                                                        | Candidate for explicit local/view graph. Method inspected in 22.2.1 declarations, not yet integrated or validated across versions. Never export generated TCB-local symbols as original user declarations.                                                                                                                                                                                                                                                                                                        |
| EVAL  | TS-based safe partial evaluation of constants, arrays, objects, spreads, references and recognized wrappers                                                                        | A bounded public-TS evaluator is implemented in `angular-core.mjs` for the new proof. Angular also has internal `PartialEvaluator`, `Reference`, `DynamicValue`, and `TypeScriptReflectionHost`; installed declarations were inspected, but these are not a supported extension API. Compiler-cli package exports block arbitrary internal deep imports. Prove a version-specific access path or implement a bounded evaluator; do not execute application functions. Keep dynamic reasons and dependency traces. |
| RULE  | Versioned semantic recognizers for Angular APIs/metadata with TS symbol identity + EVAL                                                                                            | Implemented for the tested DI/providers/bootstrap/router/host/query/framework subset; additional forms/reactive rules remain proposed. Public runtime API signatures define constructs, but do not themselves expose a whole semantic graph. Rules must distinguish user wrappers from framework functions and preserve unknown wrapper effects.                                                                                                                                                                  |
| RES   | Compiler-resolved resources, original source maps, optional CSS/i18n/animation parsers                                                                                             | Template mapping exists for direct external/literal inline templates. Styles/transforms and additional parsers remain proposed.                                                                                                                                                                                                                                                                                                                                                                                   |

The adapter should return plain version-neutral DTOs and capability flags. Internal compiler symbols/ASTs stay within the worker. API existence is an implementation lead, not proof of semantic coverage or stable support. The inspected metadata/resource declarations are in the pinned Angular compiler source: [metadata API](https://github.com/angular/angular/blob/fb7711f87d293ba1a282f21d0e9c1ef651c1b343/packages/compiler-cli/src/ngtsc/metadata/src/api.ts), [template checker API](https://github.com/angular/angular/blob/fb7711f87d293ba1a282f21d0e9c1ef651c1b343/packages/compiler-cli/src/ngtsc/typecheck/api/checker.ts), [resource registry](https://github.com/angular/angular/blob/fb7711f87d293ba1a282f21d0e9c1ef651c1b343/packages/compiler-cli/src/ngtsc/metadata/src/resource_registry.ts).

## Detailed prerequisites for the highest-risk graph joins

### DI: requests, registrations, and contextual resolutions

Implement A11 and A12 as separate passes first. A request records what source code asks for; a registration records what one scope declares. Neither requires a complete injector hierarchy to be useful. `@Injectable({providedIn: null})` identifies an injectable class without registering it in root. Recognize additional service/injection APIs only where the installed Angular package exports them; Angular 22.2.1 declarations inspected here include `Service` and `injectAsync`, which are not yet prototype-supported.

The safe static evaluator should return structured values: primitive, symbol reference, array, object, known wrapper, or unknown with reason/source. Preserve origin spans through imported constants and spreads; track dependency files. It must not invoke user/provider/lazy-loader functions. A recognized `forwardRef` can unwrap a statically returned symbol. Unknown branches/functions remain unknown; extracting known parts of an array must retain an unknown-tail record.

Construct contextual resolution only after bootstrap/route/template placement is available:

1. Resolve the requested token and lookup modifiers; preserve unknown flags/token.
2. Establish the lookup start context, host boundary, and view/content visibility. Use the logical Angular structure, including same-element directives and view boundaries.
3. Traverse the appropriate injector lookup rules. Record visited scopes, ignored registrations, possible unknown registrations, and the selected/candidate registrations. Derive implementation/alias/factory dependencies separately.
4. Handle multi registrations, provider order and alias/factory cycles with version-tested rules. An alias targets another token and requires resolution in its proper context; it is not an immediate implementation equivalence.
5. If an unmodeled registration/context can change the winner, return candidates/unknown. An optional miss permits null; an ordinary missing request can be a static diagnostic only when the modeled search is complete.

Source-defined component children and routes give possible placements; loops, recursion, projection, dynamic creation and external consumers require a finite context summary or widening. Define this policy before exposing “resolve provider.” An absent provider edge never proves a service is unused.

### Routes and feature boundaries

Represent a routes array/route object definition separately from each installation/mount. One array can be mounted under two parents with different full paths, injectors and relative navigation contexts. Preserve each sibling's order even when paths are equal. Store lazy module import, exported symbol selection, loader callable and target route/component as separate observations so unknown stages remain visible.

Feature roots should originate in applications, route mounts, known dynamic rendering sites and declared public/test boundaries. Traverse template uses, DI requests/resolutions, code calls and imports under an explicit edge policy. A reachable route is a possible activation path; guard results and runtime matchers remain conditions. A raw import edge is not sufficient to mark an entire imported module's contents runtime-reachable.

### Entry points and unused-symbol candidates

Implement framework roots (A18), host expressions/listeners (A08), dynamic rendering (A17), and test/public policies (A25) before making a global unused claim. Evaluate individual callable declarations/overrides, not only method names. Include inherited and externally callable members, pipe transform, lifecycle hooks, registered guards/resolvers/initializers, CVA/validator callbacks, render/destroy callbacks, outputs, reflected/dynamic call limitations, and template-only usage.

A useful first query returns candidates with `analyzedUnits`, incoming observations, framework roles, public/test policy, unresolved potentially relevant sites, and exclusion reasons. “No observed incoming relation” is an index fact. “Unused” is a policy conclusion requiring sufficient coverage. Report `blocked-by-coverage` or `candidate`, rather than silently turning missing family support into a deletion recommendation.

## Indexer architecture and persistence requirements

Suggested pipeline:

```text
workspace/config discovery → version-isolated program worker
  → TS symbol registry + Angular compiler adapter
  → source occurrences + family extractors + analysis issues
  → contextual/derived passes (DI, routes, impact)
  → validated snapshot transaction → graph/query API → CLI/MCP
```

The compiler worker uses the target workspace's own Angular/TS installations, checking package/peer compatibility. Isolate workspaces with different versions. Reuse one compiler program across TS and Angular passes. Never persist AST/compiler objects. Current `loadProject` forces strictTemplates with retained fine-grained overrides and fails on compiler diagnostics; production indexing needs a documented exact-config versus analysis-config policy. A failed family/unit can be reported as partial while preserving unaffected results, but must not publish a misleading complete snapshot.

| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Indexes should support `(workspace, unit, snapshot, symbolId)`, edge `from/type` and `to/type`, file/span lookup, context ancestry, token registrations per context, route sibling order/mount, and issue family/location. Token descriptions, selectors, method names and route paths are searchable properties, not unique keys. Materialize aggregate dependencies only when they can be invalidated with their evidence.

The MCP server is a thin interface over indexed snapshots. It should not embed extraction logic in handlers or regenerate the full graph for every question. Start with read queries plus an explicit indexing operation. CLI and MCP use the same query service.

Opaque cursors bind to a snapshot and filters. Enforce node/edge/path/time limits and return truncation explicitly. Provide a source evidence read endpoint/resource keyed by occurrence ID; return small original spans, not generated TCB source or the whole repository.

Use declared input/output JSON schemas and structured results. Protocol-defined `structuredContent` and output-schema validation are documented in the [MCP tool specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools). Mark read tools appropriately, and keep indexing mutations distinguishable. Transport/SDK/protocol-version choices should be verified when implementation starts. Proposed names above are not an implemented MCP API or a CodeGraphContext compatibility contract.
